# セルフレビュー self-gate（push 前）

PR を出す前に、**自分が書いた差分を自分で点検する**最終ゲート。CI 上の `claude-review.yml`
（fresh context の自動 PR レビュー）と Codex / CodeRabbit が後段で回るが、**push 前にローカルで
一度自己点検しておくと、明白なミスを PR に出す前に潰せる**（レビュー往復が減る）。

## 適用タイミング（When to Use）

- `codex-pr` スキルの **push（手順 4）の直前**。コミットは済み、まだ push していない状態。
- 既存 PR への追加コミットを push する前（Codex 指摘の修正 push 含む）。

## 自己レビューの肝（なぜサブエージェントか）

実装したのと同じ思考の流れでそのまま見直すと、**自分の判断を正当化するバイアス**で粗を見逃す。
そこで点検役を **別コンテキスト**に切り出す：

- 第一候補：ビルトインの `/code-review` スキルが使えるならそれを実行（現在の diff を対象に
  バグ・重複・簡潔化観点でレビュー）。
- 代替：Agent ツールで汎用サブエージェントを起動し、**diff と下のチェックリストだけ**を渡して
  レビューさせる（実装意図は渡さない＝外部レビュアーに近づける）。

## 手順（How It Works）

### 1. 差分を確定

```sh
git diff main...HEAD --stat   # 対象差分の俯瞰（base は通常 main）
```

### 2. セルフレビュー実行

`/code-review` が利用可能ならそれを実行。無ければ Agent ツールで以下のチェックリストを渡して
レビューさせる（**プロジェクト固有の不変条件を最優先**。一般論は控えめに）：

- データモデルの単一の真実：データ型 / JSON I/O が `Shared/` に集約されているか。
  `GameRuntime` / `Battle` が直接 JSON を読む・型を二重定義していないか。
- 当たり判定のフレーム正しさ：startup / active / recovery、hitbox×hurtbox の AABB、
  pushbox の押し合いが 1 フレーム単位で正しいか（多段ヒット / 判定出っぱなし / すり抜け）。
- データ駆動の後方互換：JSON スキーマ変更が既存キャラ JSON を壊さないか。
- Must Never の再導入：フォルダ構成変更 / 既存コード削除 / 無断ライブラリ追加 /
  MUGEN 素材・名称の流用が混入していないか。
- docs 同期：データ仕様変更で `docs/DataFormat.md`、戦闘仕様変更で `docs/BattleSystem.md`
  を同 PR 内で更新したか。
- GUI 変化があるのにスクショ（`docs/screenshots/`）が無くないか。
- [CLAUDE.md](../../../CLAUDE.md)「ビルド / 環境の罠」の再導入がないか。

### 3. 指摘の仕分け

| 指摘の種類 | 対応 |
|---|---|
| 確信があり小さい（誤字・明白なバグ・docs 同期漏れ・命名） | **その場で修正**し、`./gradlew build` 緑を再確認してコミットに含める |
| 設計判断を伴う / 影響が大きい / 自信が持てない | 直さず、PR 本文の `## セルフレビューで残した論点` に「何を / なぜ保留か」を明記し、後段の Codex / CodeRabbit / CI Claude レビューに委ねる |
| 指摘なし | その旨を PR 本文の `## セルフレビュー` に 1 行記す |

### 4. PR 本文へ反映

`codex-pr` の PR テンプレートに次の節を加える（後段レビュアーへの申し送り）：

```markdown
## セルフレビュー（push 前 self-gate）
- 修正済み: <その場で直した点／なければ「なし」>
- 残した論点: <保留した点と理由／なければ「なし」>
```

### 5. codex-pr に戻る

push（手順 4）→ PR 作成 → `@codex review` → 自走ループへ。CI の `claude-review.yml` と
CodeRabbit は push を契機に自動で回る。

## やってはいけないこと（Must Never）

- セルフレビューを「実装と同じ視点でざっと読み返すだけ」で済ませる（バイアスで形骸化する）。
- 自信のない大きな変更を self-gate 段階で強引に直す（後段レビューの論点として残す方が安全）。
- セルフレビューを理由に Codex / CodeRabbit / CI Claude レビューを省略する（3 系統＋self-gate は補完関係）。
